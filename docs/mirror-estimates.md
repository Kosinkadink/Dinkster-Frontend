# Mirrored estimates

The schema can declare a frontend-renderable mirror on a node (`mirror` field: `kind`, `precision`, optional `tolerance` and `grammarVersion`). For `kind: "expression"` mirrors at grammar version 1 the canvas evaluates the node's expression locally over stored widget values, widget-tap defaults, value-source literals, schema-declared primitive known values, exact or retained producer scalars, and upstream expression-mirror estimates. Mirror dependencies evaluate recursively, independent of document order, so a calculated output can feed the next mirror through either a link or named net. The producing node shows an "Estimated locally" result panel for every declared scalar output, and downstream link-driven widget rows show the corresponding companion estimate.

An estimate paints in the estimate accent color, and a downstream estimate's tooltip reads "Mirrored estimate (computed locally, not executed)". Estimates are presentation state only: they are derived per overlay pass, never stored, and never feed compile, hashing, or submission. Provenance remains explicit: frozen and exact values remain exact, retained values remain cached, and mirrored values remain estimates. Exact and cached producer scalars may feed a new downstream estimate and take precedence over that producer's local estimate. Stale recorded values never feed a new estimate; when the live inputs remain resolvable, a fresh local estimate replaces the stale display without changing the recorded value.

Derivation fails closed for data dependencies: an unavailable or stale producer, a cycle, a non-scalar or unresolvable variable, or an unsupported grammar version yields no estimate for that node and its dependent suffix. A structurally invalid expression publishes its canonical evaluator message even while an operand is unavailable. Runtime evaluation failures do the same once all inputs resolve. In either case, the producing node keeps a red `Preview error` panel while its dependent suffix remains absent. Editing an expression or source, disconnecting or reconnecting a link, and changing an eligible producer value re-derive the affected dependency cone. The TypeScript evaluator (`packages/core/src/mirror/expression.ts`) ports the backend expression grammar v1 and is pinned to the backend's vendored parity vectors by sha256 (`packages/core/test/fixtures/math_expression_v1.json`).

Expression text remains freely saveable, including incomplete or invalid
drafts. After commit, the existing mirror preview uses the same evaluator to
show a visible and accessible error instead of a value. This keeps completion
and persistence independent and adds no second grammar or Math-specific widget
renderer.

The `execution.mirrorPreviews` setting (Execution section, default on) and each node's override gate derivation. A disabled upstream mirror cannot feed a downstream estimate. Frozen snapshot tabs never estimate.

It includes primitive identity chains, unordered three-node calculations, link and named-net propagation, numeric and Boolean coercion, exact/cached precedence, stale exclusion, cycles, evaluation failures, invalid-text persistence, accessible preview errors, and per-node gates. Browser proof is `packages/e2e/tests/mirror-estimates.spec.ts`, which decodes the generic primitive-known-value and scalar Math Expression contracts and proves an exact primitive feeding a three-deep calculated-output chain, producing-node and downstream estimate display, provenance precedence, producer errors with downstream clearing, disconnect/reconnect, destinations without widgets, live edits, and the setting gate. `packages/e2e/tests/text-completion.spec.ts` proves invalid text saves while its error appears in the accessible preview.

## Selected asset output estimates

An output can declare `represents: { input, rendition, applies? }`. When `rendition` is `decoded-image`, the named asset-widget input holds a renderable image, and every optional combo scope matches the node's stored DynamicCombo selections, the selected asset is also presented as a pre-execution estimate attributed to that exact output. Unknown rendition kinds and unsatisfied scopes fail closed. The estimate reuses the selected-asset decode cache and remains presentation-only: it is never stored, hashed, compiled, or submitted.

Current executed imagery always wins. A represented estimate may fill an absent panel or replace retained cached imagery, but never replaces current execution imagery. The global `execution.mirrorPreviews` setting, per-node override, and frozen-tab suppression apply exactly as they do to expression and GLSL estimates. With estimates disabled, the node can still show the ordinary unattributed selected-input preview. Because a represented estimate identifies the exact output it stands for, it can feed a downstream GLSL mirror before execution.

Unit coverage is `packages/core/test/dinkster-wire31.golden.test.ts` (strict decode and malformed-input refusal), `packages/app/test/node-previews.test.ts` (execution precedence), `packages/app/test/scene-overlays.test.ts` (rendition and scope gating, exact output attribution, toggle behavior, and downstream propagation), and `packages/app/test/menu-target.test.ts` (per-node menu capability). Browser proof is `packages/e2e/tests/represented-output-estimates.spec.ts`, which uploads an image and proves the estimate before execution plus the setting gate.

## Image estimates (glsl mirrors)

For `kind: "glsl"` mirrors the schema carries one GLSL ES 3.00 fragment shader whose uniforms bind to the node's inputs by id: each image input binds as `sampler2D u_<id>` read with `texelFetch`, and each float/int/boolean/combo input binds as a scalar uniform named by the input id (a combo binds as the index of the stored value among the schema's declared options). The canvas runs the shader on a WebGL2 context and paints the result as the node's preview panel, captioned "estimated" with the same approximately-equal prefix (U+2248).

The optional `applies` scope maps combo input ids to the option keys the shader faithfully computes. A scoped mirror derives a binding only when every named combo resolves to a covered option; any other selection yields no estimate, because outside the scope the shader would compute a DIFFERENT operation than the backend - a wrong estimate, not a missing one. This is how a multi-operation node (such as `dinkster.image.filter`, whose gaussian_blur and sharpen branches are mirrored while its noise/quantize/morphology branches are not) ships a partial mirror without ever painting a misleading preview. Uniform naming stays by declared leaf id: an input inside a DynamicCombo branch binds under its plain schema id (`radius`, not `operation.radius`), and a DynamicCombo selector's value is read from node dynamic state (the elaborated branch's single source of truth), never from stored widget values.

Binding derivation (`packages/core/src/mirror/glsl.ts`) follows the same client-resident discipline as expression estimates: scalar inputs must resolve to stored widget values, widget-tap defaults, or value-source literals, while each image input must trace to a producer output. The estimate renders only when the node's single image input's producer currently shows decoded imagery attributed to the exact output the input is wired to: executed-output previews, represented asset estimates, and unambiguous single-image-output GLSL estimates carry an output id, which must equal the binding's driver output. Imagery without output-level provenance - an ordinary selected input asset, artifact, live frame, or peek rendition - never feeds an estimate, because a producer's panel can show imagery that is not the produced output (a transform node displays its selected input asset before running). Mirrored nodes are evaluated in dependency order so estimates can propagate through a chain in one overlay pass; cyclic components and ambiguous-output mirrors abstain. A node showing a current-proof execution preview keeps it. The estimate runs at the upstream preview's decoded resolution, which is sound for the pointwise shaders the contract supports.

Everything fails soft: an unsupported binding, a missing WebGL2 context or float-buffer extension, a compile/link failure, or a lost context yields no estimate rather than an error. Display output presents with opaque alpha because decoded preview imagery carries synthetic alpha padding whose transform is meaningless for display. Computed frames live in a bounded per-host cache (`packages/app/src/mirror-image-previews.ts`) holding one slot per node, keyed by shader source, upstream frame identity, dimensions, and scalar values; chained source identities use a compact SHA-256 digest while cache comparisons retain the exact full key. Connection, reconnection, or value changes therefore invalidate only the affected downstream suffix. Failures are cached too, so a failing shader does not retry every frame, and when more nodes are on screen than the cache holds the overflow nodes show no estimate rather than thrashing recomputes. The runner's compiled-program cache (`packages/app/src/mirror-glsl-runner.ts`) is bounded the same way: least-recently-used shader programs are deleted on eviction, and a failed allocation releases every handle it created.

The same `execution.mirrorPreviews` setting gates image estimates; frozen snapshot tabs never estimate.

## Per-node override

Each node can override the global `execution.mirrorPreviews` setting through the canvas context menu: the "Mirror Estimates" submenu offers Inherit / On / Off, writing the document's `mirrorPreviews` node field (`node.setMirrorPreviews` command; absent = Inherit). The effective gate for a node's estimates - expression and image alike - is its override when set, else the global setting. Overrides never bypass the frozen-snapshot rule. Like `previews`, the field is display-only and excluded from the semantic hash, so toggling it never invalidates caches or reruns anything.

The submenu appears only for node types whose schema declares an estimate this frontend can evaluate (expression grammar v1, GLSL, or a `decoded-image` output representation); on a mixed selection it acts on the capable nodes only, and it stays hidden when no selected node is capable - an override on a node that can never estimate would be dead state.

Unit coverage is `packages/core/test/mirror-previews-override.test.ts` (command, hash neutrality, validation, menu contribution) and `packages/app/test/scene-overlays.test.ts` (per-node gating over the global setting and the frozen rule).
