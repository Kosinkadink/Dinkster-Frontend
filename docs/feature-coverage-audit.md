## Purpose

This living audit tracks promised-vs-implemented-vs-tested status for every schema construct and frontend surface. Update it whenever a gap is closed or a new construct or surface ships. A green suite does not mean the feature is covered. This document exists because 143/143 end-to-end tests passed while a promised core feature, subgraph boundary bindings through conditional dynamic constructs, was still a hard rejection.

### Widgets

Registered widget kinds: INT, FLOAT, STRING, BOOLEAN, COMBO, COLOR, ASSET, and SAVE_TARGET.

Ordinary STRING widgets expose compatible Single line and Multiline views. The
schema's `multiline` hint chooses the default; an explicit representation set
can restrict or lock the alternatives. Switching through the visible row
affordance, keyboard mirror, or context menu writes only node view state, so
values, links, compilation, and execution identity stay unchanged. The native
palette lists one Text primitive while legacy multiline Text workflows remain
loadable through their search-hidden node type.

The complete source inventory and explicit disposition matrix is maintained in
`docs/widget-editors.md`. INT, FLOAT, STRING, COMBO, COLOR, ASSET, and
SAVE_TARGET keep compact-first controls and use small anchored popovers for
optional expanded editing. ASSET alone uses the shared native product dialog.
BOOLEAN is an undoable inline toggle and intentionally has no fake expanded
surface. Popovers are non-draggable/non-resizable, named and described,
Escape/outside-dismissible, and clamped to the canvas viewport without making
the background inert. ASSET remains focus-contained, native-Escape/close
operable, opener-focus-restoring, touch/keyboard operable, and internally
scrollable. Blur alone never commits a popover and Cancel/Escape discard. An
outside pointer commits a changed valid eligible non-modal field as one undoable command,
closes, and continues to its original target; unchanged or invalid text closes
without a write. Eligible fields are INT, FLOAT, single-line STRING, COLOR,
SAVE_TARGET, and raw JSON. COMBO still requires an option activation, while
value-source multiline STRING closes without committing. Specialized
explicit commit, Enter/Ctrl+Enter, validation, schema-owned
constraints/metadata, disabled/read-only, and history paths are preserved.

### Widget tap parity

Widget taps are producer affordances on widget rows, so they match ordinary
output pins where the behavior is about pointing at or dragging a producer.
The remaining differences preserve tap addressing and visibility semantics.

| Behavior | Tap parity | Rationale |
| --- | --- | --- |
| Hover growth | Same as a pin: the exact hovered tap grows to 1.35x, while a same-id real output stays at base size and vice versa | Fixed in this slice; hover identity includes the tap discriminator |
| Remote link-drag presence | Same dashed remote noodle, anchored at the tap geometry from a `widgetTap` origin | Fixed in this slice; the origin carries the widget input id used by tap links |
| Tooltip | Same pin-style Output title and type line, using the tap label or input id | Fixed in this slice |
| Body-drop snapping | Excludes taps and the narrow rendered socket-adjacent lanes | A body drop resolves to real ports only; an explicit tap hit retains its own source path. Left/input and right/output lanes use `PIN_HIT_RADIUS` depth, a subpixel viewport-scale tolerance at the inclusive boundary, and current visible real-pin centers, so browser coordinate quantization, compact gaps, resize/collapse, dynamic rows, scene replacement, and viewport transforms follow scene geometry while true interior points keep ranked preview/commit (`canvas/test/interaction.test.ts` "node-body link drops"; `e2e/tests/link-drop.spec.ts` "quantized socket-lane boundaries refuse body autosnap while the interior still previews and connects") |
| Visibility and reveal | Deliberately conditional | Taps are painted and hittable only while connected, their node is hovered, or they are legal drop targets |
| Drop-target identity | Deliberately distinct `:tap` key | `dropTargetKey` prevents a tap from colliding with a same-id real output (`renderer.ts`) |
| Context menu | Deliberately maps to the widget target | Tap actions operate on the widget value they front (`app/src/menu-target.ts`) |
