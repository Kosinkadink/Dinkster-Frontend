# Resources

Open **Resources** from the left bar to inspect the connected backends. The stored panel identifier remains `memory`, so existing layouts and backend links still open the same panel. The open workflow's backend starts expanded. Other backends are compact rows with their total card usage; disconnected backends remain listed without numbers or controls. Backend-targeted navigation supplies a fresh `focusBackend: { id }` request to Resources; it expands that row without closing other rows, including repeated jumps to the same backend.

Each graphics card has its own memory bar, two-minute usage graph and loaded-model list. The list uses the bytes resident on that card, not a model's combined host and device footprint. Allocator-held-unused memory is reserved minus allocated, not reserved minus model residency. The residual is labeled Other memory because it also includes backend non-model allocations and driver overhead. Known model and allocator-held-unused segments remain independent: one missing source does not hide the other. With neither source, or if the known parts exceed measured usage, the bar shows measured usage only. Missing figures are omitted rather than displayed as zero.

Graphs use elapsed timestamps in a bounded two-minute, 120-sample in-memory window. They do not invent history before the panel was opened. Closing the panel or reloading clears the local history. A dashed line shows the card's memory limit when reported.

**Details** holds peak usage, free memory, allocator-held memory and reported system memory. Reset sits immediately before the peak value. **Limits** holds per-card memory limits, backend headroom and Aimdo policy. Cards with measured capacity use sliders, including when no budget is reported: the initial slider spans the measured capacity and reads Automatic until changed, without inventing a graph limit or saving a setting. Devices without measured capacity do not create card blocks. Other configured or reported residency entries appear under **Other limits**, including system memory, disk and unmeasured cards. Exact fields display decimal GB and also accept integer bytes or the backend's K/M/G/T sizes. **Automatic** removes an explicit budget after Apply; it does not write a zero budget. Apply is disabled when exact-value edits are reverted to the saved values. Unknown residency names are preserved. Writable settings follow the backend's granted runtime categories. Aimdo policy applies to subsequently started workers; existing workers retain their applied policy.

The panel prefers pushed telemetry and falls back to polling when updates stop. Initial loading ends on either data or an error; dismissing the error does not restart the loading message. A stale connection disables actions, and a disconnected backend hides retained numbers. Unload requests use stable consumer and item identities, require confirmation and report failures without replacing missing values with estimates.

The backend does not yet report authoritative live-run model use. Resources does not infer that relationship from running job counts or claim to protect active models from unloading. That engine contract is tracked separately from the panel.
